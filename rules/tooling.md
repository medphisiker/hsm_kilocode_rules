# Инструментальные правила (Tooling) - HSM

Эти правила описывают стандарты работы с инструментами в проекте HSM.

## 📝 Документация и ADR
- Любые значимые архитектурные решения фиксируются в виде ADR в папке `docs/adr/`.
- ADR должны иметь порядковый номер и статус (Proposed, Accepted, Rejected, Deprecated).

## 🌿 Git и Коммиты
- Коммиты должны быть атомарными.
- Формат: `type(scope): description` (например, `feat(core): add container support`).

## 🐞 Отладка и исправление ошибок
- При возникновении ошибки попробуй исправить её самостоятельно на основе контекста.
- Если ошибка повторяется или не ясна, **обязательно** обратись к `context7` для получения актуальной документации.
- Если после исправления на основе документации ошибка сохраняется, проведи глубокий поиск и в `context7`, и в **Интернете** (Tavily/Brave Search).
