# Git Context: HSM

## 🗺️ Карта репозиториев

Проект использует структуру вложенных репозиториев (Nested Repositories) для изоляции настроек агента от кода продукта.

### 1. Основной репозиторий (Root)
- **Путь**: `.` (корневая директория)
- **Назначение**: Исходный код продукта Hyper Stack Manager (HSM), документация, тесты.
- **Ветка по умолчанию**: `main` (или актуальная рабочая ветка).
- **Правила**:
    - Содержит код в `src/`, тесты в `tests/`, документацию в `website/`.
    - `.gitignore` должен исключать `.kilocode/` (кроме случаев, когда это submodule, но в данном контексте это nested repo).

### 2. Репозиторий настроек (Kilocode)
- **Путь**: `.kilocode/`
- **Назначение**: Хранение правил, навыков (skills) и Memory Bank агента.
- **Тип**: Вложенный Git-репозиторий.
- **Правила**:
    - **Изоляция**: Изменения в `.kilocode/` должны коммититься отдельно от основного кода.
    - **Команды**: Все git-операции для этого контекста выполняются внутри директории `.kilocode/`.
    - **Содержимое**:
        - `rules/`: Проектные правила и Memory Bank.
        - `skills/`: Навыки агента.

## 🔄 Рабочий процесс (Workflow)

### Синхронизация
1. **Код продукта**:
   ```bash
   git add src/ tests/
   git commit -m "feat: ..."
   ```

2. **Настройки агента**:
   ```bash
   cd .kilocode
   git add rules/memory-bank/active.md
   git commit -m "docs: update active context"
   cd ..
   ```

### Исключения (.gitignore)
В корневом `.gitignore` должно быть правило:
```
.kilocode/
```
Это предотвращает случайное добавление настроек агента в основной репозиторий продукта.
